用戶提出新要求、修改或回報問題時，必須先複述，確認後才實作。

1. 用香港繁體中文以自己的話複述：目標、範圍（會改邊度，如已知）、不會做的事（不順便改動的項目）、不清楚處（假設／疑問，請用戶決定）。
2. 複述後停低，問「我理解啱唔啱？」，等用戶回覆。
3. 用戶明確確認（如「啱」、「確認」、「可以」、「做啦」）後才實作。
4. 用戶糾正則修正後再複述，直至確認。

確認前禁止：改／新增／刪除檔案、啟動 workflow（含 `run_workflow`）、執行改變狀態的指令（如 git commit、安裝依賴）。
確認前允許：回答問題或解釋；為令複述準確而做最少量唯讀查證（如確認路徑）。

免複述（直接做）：
- 純發問、討論、分析（無改動要求）
- 用戶明示「唔使確認，直接做」
- `commit`：只 commit 用戶講明或本次改動的檔案，message 由我決定，完成後告知
- `push`：只推新 branch；推 main/master 仍須確認
- 唯讀：`status`/`diff`/`log`
- 單純執行：build、test、`node --check`
- 啟動／停止 dev server
- 單字接續已確認工作：「繼續」「下一步」
- 內容明確指定的小改動（如「第 3 行 X 改成 Y」、改 typo）
- 還原自己剛做的改動（「undo」「還原」）

以下仍須複述：刪除檔案／資料夾、`push --force`、`reset --hard`、刪 branch、推 main/master、描述性要求（如「修好 bug」「加功能」）。
