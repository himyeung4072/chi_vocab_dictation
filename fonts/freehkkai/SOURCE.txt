Modifications made by this project (CC BY 4.0 section 3(a)(1)(B): indicate if modified)
---------------------------------------------------------------------------------------
1. Format: TTF (TrueType outlines) converted to WOFF2 (Brotli).
2. Subsetting and slicing: the font is cut into 53 WOFF2 files (freehkkai-01 .. -53) so a browser only
   downloads the slices holding the characters actually shown; freehkkai.css maps each slice with
   unicode-range. Only these code points were kept (7,040 of the 14,061 in the original):
     - all 4,819 Han ideographs of the original (CJK Unified Ideographs, Ext A, Compatibility);
     - Basic Latin, Latin-1, Latin Extended-A/B, General Punctuation, Letterlike Symbols, Number Forms,
       Arrows, Enclosed Alphanumerics, Geometric Shapes;
     - CJK Radicals, CJK Symbols and Punctuation, Hiragana, Katakana, Bopomofo, Enclosed CJK,
       CJK Compatibility, CJK Compatibility Forms, Small Form Variants, Halfwidth and Fullwidth Forms.
   Exact ranges (intersected with the original's cmap): U+0020-007E, U+00A0-024F, U+2000-206F,
   U+2100-21FF, U+2460-24FF, U+25A0-25FF, U+2E80-2FDF, U+3000-30FF, U+3100-312F, U+3190-33FF,
   U+FE30-FE6F, U+FF00-FFEF, plus Han U+3400-4DBF, U+4E00-9FFF, U+F900-FAFF.
   Removed: the other 7,021 code points of the original (Greek/Cyrillic/Armenian/Arabic/Indic/Thai/
   Hangul/Ethiopic/Canadian Aboriginal/Braille/mathematical and other symbols etc.), which a Chinese
   dictation app does not use.
3. Tables dropped by the subsetter: morx, feat, FFTM (Apple fraction/ligature feature tables, none of
   which affect Chinese text) and Macintosh-platform name records. The Apple "prop" table is only kept
   in slices 01-02 (the Han slices have no use for it). Windows-platform name records,
   including name ID 0 (copyright / licence statement), are kept unchanged in every slice.
   Hinting is not present in the original and not added. Glyph names are not kept.
4. Glyph shapes were NOT modified: for all 7,040 kept code points, outline coordinates and advance
   widths in the slices are identical to the original TTF (checked by script). Ascent/descent and
   other vertical metrics are identical in all slices.

Tools (development machine, temporary venv, not part of the project)
-------------------------------------------------------------------
Python 3.13.14, fontTools 4.59.0, Brotli 1.1.0 (pip, pinned). fontTools.subset options: flavor=woff2,
hinting=False, notdef_outline=True, glyph_names=False, layout_features=*, name_IDs=*,
name_languages=*, legacy_kern=False. Slice order was decided with Unicode 16.0.0 Unihan.zip
(https://www.unicode.org/Public/16.0.0/ucd/Unihan.zip, SHA-256
b8f000df69de7828d21326a2ffea462b04bc7560022989f7cc704f10521ef3e0; used only on the dev machine to group
characters, not shipped): fields kGradeLevel (Hong Kong primary grade 1-6, from the Longman
Elementary Chinese Dictionary), kHKGlyph (index into the 2000 revised edition of the HK 常用字字形表,
not the 2007 edition the font claims), kBigFive.

Slice layout
------------
freehkkai-01   Latin, punctuation and symbols (1,091 code points)
freehkkai-02   CJK symbols, kana, Bopomofo, fullwidth forms, enclosed/compatibility (1,130)
freehkkai-03..37  2,599 Han characters that Unihan kGradeLevel lists for HK grade 1-6, grade order, 75 per slice
freehkkai-38..52  2,183 further Han characters listed in kHKGlyph, up to 150 per slice
freehkkai-53   37 remaining Han characters of the font
Total WOFF2 size 2,753,112 bytes (53 files); freehkkai.css 46,790 bytes (generated, 53 rules, each with
font-display: swap and unicode-range). SHA256SUMS.txt lists every file in this folder except itself and
SOURCE.txt.

Integrity checks run on the generated files: every slice's cmap equals its planned code point set; the
slices do not overlap and their union is exactly the 7,040 kept code points; each unicode-range in
freehkkai.css decodes back to the same set; outlines and advance widths equal the original.

Reproduce (the build scripts are intentionally not kept in the project)
-----------------------------------------------------------------------
1. Download the TTF above and check its SHA-256.
2. For each slice, load the TTF with fontTools, subset to the code points listed for that slice
   (options above), set flavor "woff2" and save. Slice membership: see "Slice layout"; inside a grade or
   group the characters are ordered by Big5 code (Unihan kBigFive), then by code point.
3. Write one @font-face per slice with unicode-range = the slice's code points (consecutive code points
   joined into ranges).

Claims and limits
-----------------
- "Based on the 常用字字形表 (2007年重排本) / 4,762 primary-school common characters" is the authors' own
  statement (see the notice files). It has NOT been independently verified by this project, and nothing
  here claims that the font conforms to the Hong Kong Education Bureau standard.
- The authors state the font is derived from 台灣全字庫正楷體, which is licensed under several terms
  (links in the notice). This project has not reviewed those upstream terms and relies on the authors'
  statement that the CC BY release meets them.
- The font has Han coverage of about 4,800 characters only. It does not contain, for example,
  嘅 咗 哋 啲 嚟 冇 佢 喺 (唔 is included), nor 爲 (U+7232); text outside the coverage falls back
  to the next font in the CSS stack.
